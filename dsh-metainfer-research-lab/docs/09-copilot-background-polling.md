# Copilot 覆盖工作区时的后台调度

- 打开 Copilot 时暂停被遮挡工作区的事件、专家记录轮询和倒计时；不停止 Host 上的实验、专家或调度器。
- 通知关闭时暂停常规状态轮询；首次以对话打开状态挂载仍允许一次状态初始化。通知开启时采用已有后台策略，只保留每 15 秒的状态检查。提醒可能延迟至下一次检查，短暂中间状态仍受轮询观测边界限制。
- 关闭 Copilot 立即补齐状态、事件、专家记录和当前时钟；保持快照、事件游标、去重基线与已缓存专家记录，不清空后重载。Host 事件保留上限 5000、客户端显示上限 200 不变，不承诺无限历史补齐。
- 同一挂载周期内取消或被替代的请求即使稍后成功或失败，也不得提交状态、改写游标、清除新请求控制器或重排计时器。
- 保留已有外层方角修复、滚动和原生会话功能。此变更不是新建空会话的替代路径，也不更改会话/工作区元数据。

## 验证与部署

运行 `node --test scripts/copilot-background-selftest.mjs`。可通过 `CLIENT_SOURCE_PATH` 指向安装候选；测试调用实际客户端工厂，以确定性时间、Hook 生命周期和 API 替身验证暂停/恢复、游标、通知调度及竞态。它不是浏览器布局、GPU、物理 FPS 或用户输入延迟测试。

修改包含 Hook 调用顺序变化，部署后须完整刷新客户端，不能依赖旧组件上的热替换。只替换本次钩子与调用点；不要用另一分支的整个客户端覆盖安装版，否则可能混入无关原生打开行为。其他已打开的详情/集群弹窗有独立轮询，不在这三个常规数据源的暂停承诺内。
